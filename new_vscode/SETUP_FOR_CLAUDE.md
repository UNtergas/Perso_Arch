# VS Code setup, for a Claude session on a new machine

The nvim keys for VS Code (VSCodeVim) are generated by `new_vscode/build.py` into the user's `settings.json` and `keybindings.json`.
`settings.json` and `keybindings.json` here are copies of the result; `KEY_GUIDE.md` lists the keys.

## Install

1. Install the `vscodevim.vim` extension (and `mhutchie.git-graph`; optional: `tobias-z.vscode-harpoon` for `SPC h ...`).
2. Back up `~/.config/Code/User/settings.json` and `keybindings.json`, then run `python3 new_vscode/build.py`. It rewrites only the
   block between `==== nvim keys` and `==== end of the nvim keys block ====` in `settings.json`, and appends its own entries to
   `keybindings.json` (it removes older copies first, so running it again is safe).
3. The script expects the earlier hand-written vim blocks (`s` easymotion, `]d` / `[d`) in `settings.json` the first time. On a
   machine without them add the easymotion settings (`vim.easymotion`, `vim.easymotionDimBackground` ...) by hand.
4. `lazygit` must be installed for `SPC g g` / `SPC g f`.
5. Kotlin: update `jetbrains.kotlin-server` (the old 0.0.13 bundles an expired server), and copy
   `new_vscode/gradle-init/kotlin-lsp-androidtest.gradle` to `~/.gradle/init.d/` for Android projects on AGP 8.13. Details and the headless
   test (`lsp_probe.py`) are in `KOTLIN_NOTES.md`.

## Rules

- Change the key table in `build.py`, not the generated block. Check each VS Code command id against the installed build (grep the
  quoted id in `/usr/share/code/resources/app/out`, `.../extensions/*/package.json` and `~/.vscode/extensions/*/package.json`).
- `vscodevim` only sees Ctrl keys it contributes bindings for. `Alt+key` and `Ctrl+Shift+key` go in `keybindings.json` with the
  `vim.remap` command. `ctrl+d`, `ctrl+f`, `ctrl+t`, `ctrl+n` etc. stay with VS Code on purpose (the user removed the
  `extension.vim_ctrl+...` bindings).
- Not tested in a running VS Code by the author; ask the user to try the keys under "First run" in `KEY_GUIDE.md`.
